# 2026-10-08 v0.2.6 published

[v0.2.6 Alpha](https://github.com/MaxHastings/BlocklandReImagined/releases/tag/v0.2.6)
is the public latest release, from `ef4be7de2f1833a68dd892fd3b104dfcdf613bd6`
(annotated tag `v0.2.6`). Maxwell asked to ship ("merge, publish, clean up",
"I approve everything") after the gate found the bot regressions below.

## What went in
The v0.2.6 stack: bot navigation (route seconds, every floor of a column,
measured standstill leaps, failed moves remembered per move and floor),
teammate damage (ally harm), the fog and sky fix, Create Mini-Game Set Favs,
the v0.2.6 plan and design docs, and the earlier stack (ragdolls, corpses,
crash capture, where to stand, ledge pushes, measured vehicle handling,
timed throws).

## Gate and main
- The first gate on the stack (e05a1383) failed eight bot tests. Four were
  bot driving: bisected to dc7d25f5 (every floor of a column), whose sample
  skipped a hit when the ray started inside something; a chassis's short
  reach from its height hint started the ray exactly on the ground's top,
  which the point test calls inside, so every drive search came back
  Nowhere. Fixed in ac50d6e2 by testing a hair above the origin (the
  reviewer's independent fix, `!(distance > 0 && inside(origin))`, is the
  same idea). The teamkill pair (capture_the_flag, zombie_survival, and
  all_dials_on) passes on navigation alone and on ally harm alone, fails
  merged, and ships as a known failure owned by "v0.2.7 bot teamkills".
- tools/gate.py now treats "Reapply ..." like "Revert ..." (36ef5f9c). Main's
  push hook runs origin/main's gate, which still had the old rule, so the
  stack's f26984b6 (Reapply "WIP: bots drive by measured vehicle handling")
  was refused. Main's v0.2.6 history was rewritten only in that commit's
  message (Gate-Allow-Undo for route.rs and interactions.rs) with
  filter-branch; trees are identical. The review files cite the
  pre-rewrite hashes, kept in the branch backup bundle
  (project files, branch-cleanup/v026-backup-2026-10-08.bundle).
- Gate PASSED 11eadefa (stack) and 5154b68f (main copy, idle PC: an earlier
  run with content regenerating alongside timed out two tests and crashed a
  GPU test). Main then took ef4be7de: the release workflow's two
  `bri-client --check` steps now wait for the windowed program
  (Start-Process -Wait); before, PowerShell did not wait, so the zip smoke
  read add-on-health.json before it existed and $LASTEXITCODE was never the
  game's.
