# Missing pinned Add-On dependencies in the import reference

The final bundle audit enumerated the configured Steam, vanilla v20 and archive
search roots. Missing pinned copies extend beyond Tier 1 to numerous Tier
weapons, skins and brick packs; this inventory covers those roots and the
isolated content drop only, not every possible backup. The intact previous
conversions therefore remain useful evidence, but are not current imports.

Inspection found that `reference_view` copied the vanilla Add-Ons tree and
removed an ambient version only when a pinned replacement existed. If a
selected dependency was missing, an unpinned same-name archive could silently
remain available to another import, contrary to the documented pinned-reference
contract. The fix removes any ambient same-name copy from the disposable view
before checking whether the selected source exists. The source installation is
unchanged; a missing pinned copy stays absent and the normal build reports it.

The new regression first failed because the unpinned dependency remained. After
the fix, `python -m unittest discover -s tools -p test_imported_addons.py`
passed seven tests, including selected-pin replacement and source immutability.
Python compilation and `git diff --check` passed. This does not complete or
authorize a hybrid release bundle; compatibility, honest per-package
provenance, and final package validation still need to be established. Changing
the bundler also changes the current import recipe identity, so previously
generated receipts cannot be described as newly generated by this revision.
