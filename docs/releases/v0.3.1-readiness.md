## Completion standard

Follow the original asset and behavior through conversion, authored binding,
runtime mechanism, ordinary authoritative controls, presentation, packaged build
and verification. Source appearance, materials, animation, sounds, timing,
movement, weapons, vehicles, interactions and game rules remain required where
the agreed experience uses them. A parsed resource, successful import, isolated
probe, plausible approximation or unused preserved field does not finish an
Add-On.

Every discrepancy has an implementation owner, a concrete next action and
closure evidence. A blocked package returns to its consumer after the generic
engine fix is committed. Source unknowns require investigation and a bounded
verification plan; they are not permission to invent behavior or waive it.
Requirements cannot be parked, relabeled optional or removed to make the release
look ready without Maxwell's explicit scope decision.

The private game execution plans and coverage ledgers retain their full agreed
scope. Early diagnostic/exploration milestones are steps toward that scope,
not replacements for it. The vanilla alpha contract, platform principles and
existing release requirements also remain in force.

## Integration rules

1. Keep each atomic change committed and tested at the applicable quick/focused
   tier. Combine immutable checkpoints; do not merge another worker's dirty tree.
2. Compare paths, stable IDs, generated output ownership and actual activation
   policy before combining private Add-Ons. A clean Git merge does not establish
   HUD/input/movement/animation coexistence.
3. Generic mechanisms enter the public engine. Original game assets, recovered
   source and game-specific tools/bindings remain private.
4. Run the integrated candidate gate and required Windows checks. Fix deterministic
   failures; retain honest evidence for nondeterminism and resolve release-blocking
   known issues. Never bypass the gate or add an exemption to disguise a regression.
5. Push main through `python tools/gate.py --push`. Root owns main integration;
   workers continue bounded tasks without competing main pushes.

## Final playtest and publication gate

- Pin one engine main SHA and one private Add-On main SHA, plus generated-input
  receipts and package/file hashes. Later changes require fresh affected checks.
- Verify every agreed Add-On set independently and in the supported combinations:
  source bindings/presentation, normal gameplay loops, ownership and permissions,
  host/client agreement, late join, save/reload and conflicting policy activation.
- Complete the fidelity coverage ledgers with evidence. Remaining discrepancies
  are work to finish; a list of known gaps alone is not release readiness.
- Produce an isolated combined package, outside the development environment,
  with the final coverage/test matrix, expected behavior and diagnostic logs.
  Preserve previously delivered playtest snapshots.
- Maxwell performs all interactive testing. The final all-set playtest and his
  explicit publication approval are required before release. A preview test or
  approval of an earlier commit is not approval of a later release candidate.
- Until approval: no release tag, publishing workflow, public release upload or
  update deployment. Ordinary source integration and build-only verification
  remain allowed.

This document defines the work and approval boundary. It does not mark the
engine, any game Add-On, the full alpha contract or v0.3.1 release complete.
