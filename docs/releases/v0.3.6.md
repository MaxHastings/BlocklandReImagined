# v0.3.6 Alpha — bot encounters and Zombie Hole

## For players and builders

- Bots pursue visible enemies beyond their spawn area. Their spawn remains an
  idle home, while explicit guard orders still constrain their assignment.
- Zombie Hole restores its own bot on admin and minigame resets. Repeated
  deaths and resets retain one bot per hole, and removing the hole removes it.
- Supplied Zombie artwork resolves the authored face and blank decal instead
  of keeping a random face or shirt decal.
- New wrench events let builders pause/release encounters, set sight and idle
  wandering independently, disable idle return, change body attack damage,
  and author replacement-enemy timing. `onBotSpawn` configures each life;
  `onBotDeath` can schedule the next one. See **docs/BOT-SPAWNERS.md** in the
  download for start/stop switches and timed replacement recipes.
- Zombie infection checks existing half-health eligibility before bite damage:
  crossing the threshold damages normally, while the next eligible contact
  converts a bot alive. Human players still take normal damage.

## Included Add-Ons

The existing credited Add-On selection is retained. Enable **Blockhead Bot**,
**Zombie** or **Shark** in the host's Add-Ons as wanted; they start off. Zombie
and Shark enable **Hole Bots** automatically. No separate `Bot_Zombie_L4B`
files were supplied, and this release does not include that custom mode.

Native bot controls build on the improved BRI brain and ordinary event editor.
They are not a complete implementation of the original Bot_Hole custom UI,
legacy parameter signatures, or arbitrary TorqueScript. Infection name prefixes,
markings and some team-mode adaptations remain incomplete. The existing mixed
Zombie/Blockhead Windows NaN report remains unreproduced; retain complete crash
logs if it returns.

## Verification scope

Source-backed negative controls reject the old pursuit, reset, appearance and
infection behavior. Live headless scenarios cover pursuit, actual damage,
pause/resume, idle return, interrupted encounter settings and timed respawn.
Two real QUIC clients exercise ordinary wrench authoring, late join, spawn
initialization, minigame reset and removal against the supplied original bots.
These establish gameplay/state agreement, not rendered appearance or subjective
fun. Maxwell performs interactive playtesting.

The release requires the integrated gate, matching Windows CI, three-platform
archive integrity/content checks and extracted startup checks. Final build pins
and results are recorded in the dated publication receipt. The full alpha and
AA2 mission contracts remain open; private AA/Halo source assets are excluded.
