# v0.3.5 Alpha — resources, rendering checks and imported-map gameplay fixes

## Player-visible changes

- Original menu background photos reach the generated UI content again.
  Packaging checks their actual bytes, so a complete file manifest can no
  longer hide an empty screenshot set.
- Indexed Add-On models resolve from the correct package root, removing false
  missing-animation resource reports. Player Throwing handles freshly joined
  players' unset state; sound/shake-only explosions are no longer incorrectly
  reported as having nothing to display.
- Loading Map names the work in progress, including animations, catalogs,
  collision, map surfaces, lighting and content verification. Session logs
  record each task's time rather than leaving the pre-server wait unexplained.
- GPU startup submits and checks a textured draw with depth and readback.
  Supported SDR presentation views stay consistent across surface formats and
  recovery; diagnostics report capabilities and compiler policy more accurately.
- Offscreen blended map instances are rejected before transparency sorting,
  with adjacent compatible ranges batched without changing their order.
- Player recovery respects real overhead clearance. Cosmetic casings separate
  from map surfaces after bouncing. Allied bots can yield in narrow passages;
  bounded route diagnostics help distinguish remaining stalls.
- A current README explains launching and reporting. Current optional guides
  live under docs/ and third-party notices under licenses/. Historical release
  handoffs and internal development/test cards are no longer shipped.

## Add-On mechanisms

Recent shared integration includes persistent map emitters, breakable replacement
models, map volume bounds, additional controls and owned-item lifetime renewal.
A loose-object Use release retains the original target and finishes each
subscribing Add-On's callback once, including after the target disappears or the
player dies. Existing limitations and formats remain alpha.

## Verification and limits

The integrated gate and Windows CI passed on the release revision. The actual
platform archives were checked for payload integrity and matching base content,
including the restored menu photos and existing map previews. The extracted
Windows client and dedicated server passed startup/content checks. Offscreen
world checks covered DX12 with DXC and FXC, Vulkan, and the software renderer
with the bundled default compiler. These are technical checks, not a claim of
complete original-game fidelity or interactive playtest acceptance.

The reported RX550 black gameplay world remains unconfirmed. These changes do
not claim its cause is fixed, full hardware coverage, a particular gameplay FPS,
or complete AA2 map/lighting/NPC fidelity. Original AA2/Halo assets are excluded
from the public release. Private AA2 playtests have separate receipts and
mission acceptance.

A separate compatibility check reproduced a black Bedroom world when
Microsoft's software renderer is explicitly forced to use FXC. The same device
renders correctly with the bundled default Auto compiler or explicit DXC. This
forced legacy-compiler combination remains a known limitation; it does not
establish the cause of the RX550 reporter's issue. Leave compiler selection
at its default unless collecting diagnostics.
