# v0.2.9: what Max asked for vs what shipped

Audit date 2026-10-11. Scope: every ask Max wrote in the project chat after the v0.2.8 release (2026-10-09 22:49 UTC), plus the 32-item v0.2.9 brief he attached. Checked against the merged tree (main at 079f6eb, which is PR #48), the PR bodies for #37 to #46, the `docs/progress/2026-10-11-*.md` entries on main, `release/release-notes-v0.2.9.md`, and the thread list. Thread claims were not taken on trust.

Status words: **Shipped** = in main at 079f6eb. **Partly** = some of the ask is in, some is not. **Not done** = no code or doc landed. **Finding only** = investigated, no change. **Deferred** = Max or the lane chose to leave it out.

Release state when checked: v0.2.9 is merged into main but not yet tagged or published. The latest GitHub release is still v0.2.8. The PC session refused to push the tag without a permission-list change (see ask 31).

## Headline

- 33 asks in Max's own words since v0.2.8: 15 shipped, 5 partly, 7 not done, 1 finding only, 3 deferred, 1 cannot be verified, 1 in progress (publishing).
- The 32-item brief Max attached: 13 shipped, 7 partly, 12 not done.
- The 12 not-done brief items include the whole low-risk UX group Max asked for by name (Ctrl+wheel scrolling, chat while dialogs are open, missing-content notice, router diagnostics). They were "queued until a lane frees up" in the 03:06 plan, but no thread was ever started for them. The freed lanes went to integration, CI and permission prompts.

## Why it feels like less than you posted

1. The release notes list four "New" bullets. Most of what was asked was either a deeper investigation (reported in docs, not visible in play) or a later-phase item.
2. About a third of the Rallypack/P90 handoff was written as "later" or "investigate first", and those parts got no lane.
3. The bot hardening pass you asked for (navigation, weapons, communication, driving, getting stuck) was not started. The bots thread fixed the tick cost and two crashes, and its own PR says the hardening pass "will follow separately".
4. Some shipped items are not in the notes by name (the coverage report in import reports, `require()` for Add-On operations, the Rallypack recipes now in Git).
5. Several asks were met on the safe side of the ask: for example reliable operations pre-check only three operations (`give_item`, `take_item`, `remove_brick`).
