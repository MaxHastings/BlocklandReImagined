the combined Windows x86-64, macOS Apple silicon and Linux x86-64 v0.2.1
release, including NPC work. It does not declare any acceptance item complete.

when discoveries warrant it; root publishes v0.2.1 only when fully satisfied.
Every pivot records the evidence, delivered outcome and limits here/progress.
The NPC outcome must be an integrated expressive experiment; a standalone
planner is groundwork. Favor several unseen compositions with real execution
over ungrounded provider metadata. Stack feasibility may justify an explicit
physics-based pivot; it never justifies fabricated success or silent omission.

## State vocabulary and release rule

- **Reported / unresolved:** user observed a failure; no causal repair is
  established.
- **Patch + focused evidence:** a local change has named passing evidence;
  the combined candidate and platform acceptance remain open.
- **Investigating / foundation:** analysis or a standalone mechanism exists;
  it is not delivered NPC behavior.
- **Integrated + verified:** root has reviewed integration and named combined
  checks pass. This state requires evidence, not an owner assignment.
- **Packaged / handed off:** all three platform artifacts correspond to the
  same reviewed candidate, checks and artifact hashes are recorded, and
  Maxwell receives concrete playtest instructions.

Every package records exact changed paths, commands/results, failure evidence,
unknowns and next work. Historical passing tests below describe the earlier
patch state; they are not a combined v0.2.1 verification claim. The full alpha
contract and handoff remain open after this plan.

## Sequence and ownership

1. Root reviews this inventory and reconciles other earlier reports into it.
   Initial investigations stay in three Sol High lanes: crash/stability,
   crowded-bot performance, and NPC foundation/work-plan (this lane).
2. Foundation reports grounded interfaces and actual engine limitations before
   integration. Root agrees the API boundaries and assigns capability and
   navigation work in parallel, with disjoint owned paths.
3. Root integrates objective providers, capabilities, navigation and
   cooperation. Independent review checks rule/physics truthfulness,
   authority, deterministic budgets, regressions and held-out cases.
4. Root completes the combined gate, platform checks, packaging and release
   handoff. Maxwell alone supplies interactive acceptance, including the video
   repro. A crash that is still unresolved blocks a success claim.

Owners identify responsibility, not completion. Root approved this Sol High
lane's runtime integration in `session/{bots,events,rules}.rs`,
`bots/{planning,objectives,behaviour}.rs`, `bot_kind.rs`, Blockhead `bots.json`,
`chaos/tests/bot_objectives.rs`, these audits/progress and the owned seam row.
`events/runtime.rs` permits only read-only semantic inspection helpers/tests.
Root also authorized linking the separately owned tactics/combat modules and
the narrow postmovement launch gate in `session/weapons.rs`;
performance owns those implementations, stability owns the independent
navigation spike. No commits, pushes or manifest/lockfile edits in this lane.

## Implementation decision and explicit scope pivot

Root approved an integrated expressive rule experiment with one ordinary
executor instead of ungrounded universal metadata. NPC physical Player and
MiniGame slots now match author intuition whenever catalog inputs declare
them; Bot/Driver and real quota attribution persist, no connected Client is
invented. This intentionally changes classic bot slot absence during alpha.

The initial provider composes complete supported activation/region/touch row
groups, observes real input/progress across delays, bounds discovery/grounding
and search separately, and falls back with Explain reasons and failed-action
cooldowns. Unknown relevant child/reaction/collateral semantics remain explicit.
Held-out unfamiliar names/order/count/parameters demonstrate the delivered
mechanism; they are fixtures, not authored-name runtime handlers. Broader exact
object transport/cooperative stack/tool/vehicle jobs remain the next grounded
phase with actual mechanics evidence. Canonical winner diagnostics are limited
to real round cancellation/score evidence; predictions never claim victory.
