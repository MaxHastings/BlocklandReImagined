# v0.2.2 creator and bot checks

Use a copy of your save. Start with the [creator guide](PLAYTEST.md) and
[test card](CREATOR-TEST-CARD.md). These checks target the changes since v0.2.1;
the Workshop remains an experiment, and your playtest decides how it feels.

Before hosting, try **Start Game → Colorsets...**. Select Default or Trueno's,
inspect the swatches, and press **Use**. **Folder** opens your writable
`colorsets` folder: add a named `.txt` colorset or a subfolder containing
`colorSet.txt`, return to the chooser, and select it. Cancel leaves your earlier
choice intact. This chooses the palette for new hosted worlds. When loading a brick save with
different colors, the existing color-matching choice still applies. Guests
receive the host world's palette automatically.

Blow up a few bricks with rockets and watch them settle. Explosion debris now
stays opaque for ten seconds, then fades over three. Options' Physics Quality
and the adaptive physics budget still retire older debris early under heavy
destruction; longer visibility does not increase those limits.

Try a dense selection with each Duplicator, then rotate and plant it. Large
previews may show one enclosing outline with an explicit notice; the full copied
selection should still plant. Include bricks whose rendering/collision is off.

In Graphics, compare **Classic**, **Unified** and **Dynamic** in Bedroom, Kitchen
and a dark map. Dynamic now lights current geometry without the old baked shadow
masks. Move the sun, disable shadows, break a light and destroy a wall: check that
the lighting reacts and that mode changes do not hang or leave old shadows.
Repeat rapid mode changes and a map change. Source-lamp recovery is approximate,
so record dark rooms or unexpected brightness along with your graphics preset.

## Create, then make it complicated

1. Make a plain button open a named door. Add a second rule that only closes
   it for one team. The plain row should stay compact beside the guarded row.
   **+ IF** starts an unfinished check: choose its subject/property/value
   before Send. Cancel, return, copy the brick's settings and resize the screen
   with a half-written check or number; your unfinished text should survive.
2. Open the input/output lists. Common choices come first; Add-On families
   have their own groups. Search with several gameplay words, enter a group,
   then back out. Selected legacy team inputs keep their original meaning.
   They are not rewritten into a generic input plus a delayed IF.
3. Make a two-team MiniGame. Use **Teams** to add/name/color teams and set
   their body and equipment, then **Setup** for round/scoring settings. Try
   another category while typing a number and return. Save newly created
   teams before assigning players; the server must give them their real IDs.
4. In Wrench, **Region...** opens Detection region. Resize a goal and make
   only one of two identical Steel Balls score using **Object → Spawner**.
   Copy the setup, rename a spawner and inspect any unavailable copied action.
   You should be able to remove just that row without clearing useful rows.

## Let bots use your rules

Enable Blockhead Bot, create a MiniGame and use ordinary Vehicle Spawn bricks.
Make several independent activation switches set different MiniGame variables;
guard a final winning switch on all of them. Then try ordered checkpoints,
delayed effects, changed conditions and an unreachable alternative.

For an object objective, name its spawn brick, give the goal a detection region,
and use **onObjectEnter → Instigator → winRound**, guarded by
**Object → Spawner = your named brick** and **Instigator exists = Yes**.
Put a second identical object closer to the bot. Only the named spawn should
matter. Begin with an accessible ground region; then give the bot a Gravity Gun
and raise the region. Swap the target for a driveable ground vehicle and check
that it boards that vehicle's control seat. These methods use real contact,
native holding or driving; reaching the predicted destination alone never wins.

Enable Slayer and Capture the Flag to try the package-provided pickup/return
objective. Assign bots to teams through the normal MiniGame controls. Change a
flag's color or replace an object while a bot is approaching it. Try taking its
tool away after it has started transporting the object, or getting to the
object first yourself. It should repair its plan or report a limitation rather
than claiming the old plan succeeded.

Interrupt an approaching bot with combat or a supported Add-On rest/ride action,
then let it resume. Another resting bot should not stop its planning. A paused
approach gets its travel time back; already scheduled event delays continue
passing in real time. Try replacing weapons or emptying ammunition during combat.
Watch for aim thrashing, repeated fruitless actions and failed recovery.

Planning still has finite depth/work limits and covers supported rule vocabulary.
It can ground exact spawned-object delivery, declared pickup/return and supported
native elimination rules. It does not infer arbitrary scripts, plan throws into
hoops, discover hookshot routes or organize cooperative stacking. Aircraft and
watercraft delivery are outside this slice. Explain is a diagnostic, not a promise
that every authored game can be solved. Rules-added bots without a creator
spawner do not acquire its event-authoring authority.

## Shark and sustained battles

Enable Shark and try a large water pool in a MiniGame. Check swimming, the
original body, different colors, close contact and release after death/reset,
then leave water. Repeat after changing maps and disabling/re-enabling the Add-On.
Compare the remaining fidelity limits in [known issues](../KNOWN-ISSUES.md).

Recreate the Bedroom/Beta City battle with 12–16 mixed bots, rockets, spears and
gravity guns. Change equipment while the fight continues. Headless simulation
timings cannot establish Windows frame rate or reproduce every render/audio
hang; the earlier Windows NaN crash remains open. Keep the complete crash and
session files if it returns.

Record the intention, expected result, actual result and smallest reproducing
save. Especially note confusing choices, lost edits, unnecessary scrolling and
whether mixing mechanics makes you want to write an Add-On.
