# v0.2.3 player and creator checks

Use a copy of your save. This guide covers the v0.2.3 candidate; publication,
platform checks and your interactive acceptance are separate. Read the
[release notes](V0.2.3-RELEASE-NOTES.md) and [known issues](../KNOWN-ISSUES.md).
The [creator guide](PLAYTEST.md) has the full event controls.

## Host, join and keep your choices

Choose your Add-Ons and **Start Game → Colorsets...** before hosting. Change
an Add-On, restart, then try a fresh extraction of the same new build: choices
made with v0.2.3 should follow your normal user profile. **Default** restores
that build's default Add-Ons. Old choices from a discarded v0.2.2 folder cannot
be recovered. Put custom palettes in the chooser's **Folder** location so their
files survive fresh release folders. A missing palette needs an explicit new
selection before hosting.

Join by IP with a guest who needs the host's Add-Ons. Preparation should finish
before the guest becomes a player; it should not briefly connect, leave and
rejoin. Required code still uses the existing trust prompt. Repeat after a map
change, and cancel a preparation once. Note any duplicated arrival or stuck
loading state.

## Create and recover a MiniGame

Start with ordinary round/scoring settings, then add teams, names, colors,
bodies and equipment. Save new teams before assigning players. Change category
while typing a number, return, and check the draft survived.

Store a favorite, disable one of its equipment Add-Ons and reopen the MiniGame
screen. Load the favorite: its missing choice should remain **Unavailable**.
Choose a live replacement, or **None** for an unwanted tool, before Create/Save.
A missing body needs an available body. Restoring the Add-On should restore the
original choice when loading the unchanged favorite.

In Add-On settings, try a favorite containing both normal MiniGame options and
Add-On rules. Save waits for each required step. Mutation controls pause while
it is pending; navigation and Close remain available. A rejected step must say
which step failed and allow another edit after completion or timeout. An
unsupported favorite should warn about omitted settings and protect its source
slot; store a revised version in another slot. Check that a rules-only draft
survives a refresh after a failed save.

## Make one rule, then add a condition

Wrench a button and make it open a named door. Add **+ IF** only when you need
a team/property check; finish every subject, property and value before Send.
Add a delay and change its condition before it fires: the check should evaluate
when due. Copy the settings, rename a target, and inspect any unavailable row.
Cancel/reopen with unfinished text, then save/load the build and repeat.

For an object goal, name its spawn brick and set a Detection region. Use
**onObjectEnter → Instigator → winRound**, with
**Object → Spawner = your named brick** and **Instigator exists = Yes**.
Put a second identical object nearby. Only the named object's real entry should
count. Enable Blockhead Bot and use a normal bot spawn brick in the MiniGame.
Begin with an accessible ground goal; try contact, Hammer, then Gravity Gun.
For two required entries, begin inside the region and check that it really exits
and returns. **Explain** should show this brick's bounded event/bot diagnostics;
unrelated NPC messages should not replace them. Save/load and copy the setup,
then check team rules and declared MiniGame state still belong to the loaded game.

## Check the world around the rules

- Paint an occupied vehicle's spawn brick, Wrench it, toggle **Re-Color Vehicle**
  and Send. The same vehicle should change appearance without losing its rider.
  Repeat with the setting off and with an independently painted vehicle.
- Walk, drive a Jeep and ride a Horse through linked portal openings. Try rotated
  exits, both travel directions, first/third person and a guest. A shut opening
  should block the Horse; watch for camera snaps, half hats and duplicate bodies.
- Compare **Dynamic**, **Classic** and **Unified** in Kitchen/Bedroom. Dynamic
  should preserve authored unlit surfaces while housing and shadows still react
  to lights. Change maps and return. Broader interior lighting remains approximate.
- Plant/copy near map floors and real gaps. A connection blocked by the floor
  should fail as a whole; valid clear support should still plant. During a long
  copy/cut, revoke the operator's trust or remove its only supporting anchor.
- Open administration repeatedly after a successful command, then change maps
  and reopen. Actions should recover from refresh without requiring a restart;
  stale replies must not restore permissions after a demotion.

## Repeat the reported failures

Repeat the Windows mixed-bot battle, normal death/respawn, a large destruction
burst and a tank chase where you retreat behind cover. These reports have no
established causal fix. Record the map, equipment, bot roles, graphics settings,
exact action and whether the chassis actually moves. Keep complete crash/session
files and a small reproducing save. Headless timings do not establish Windows
frame rate or eliminate restoration hitches.

Bots still cannot infer arbitrary scripts, plan jet-assisted carrying, high-hoop
throws, hookshot routes or coordinated stacking. Shark/Zombie fidelity remains
partial. The Workshop and alpha formats remain experimental; the full alpha
contract is open. Report lost edits, misleading success, confusing choices and
unnecessary scrolling as well as crashes.
